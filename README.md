# 부산 공공기관 강사 구인공고 알리미

부산 지역 공공기관(교육청·학교, 시청·구군청, 공단 체육시설, 평생학습관·도서관, 청소년·여성 기관, 시 출연기관,
국가·공공기관)의 강사 구인공고를 매일 아침 모아 **강사잇다 공고 올리기 양식(엑셀)으로 정리해 이메일로 보내주는** 프로젝트입니다.
GitHub Actions 에서 무료로 돌아갑니다.

울산판([ulsan-shcool-public-company](https://github.com/thskal17-sudo/ulsan-shcool-public-company))의 코드를 그대로 가져와
부산용으로 바꾼 것입니다 (수집기·강사 공고 판별·첨부 공고문 읽기·강사잇다 양식·state 브랜치 DB·catch-up 보충 수집 모두 같음,
캠프 수주 기능은 제외). 대학 부설 평생교육원 게시판도 함께 모읍니다 — 다른 저장소(lifelong-education-pyengsang-)도
같은 게시판을 모으므로 두 메일에 같은 공고가 나올 수 있습니다.

- 설계 문서: [docs/DESIGN.md](docs/DESIGN.md)
- 수집 대상 목록: [config/sources.yaml](config/sources.yaml)
- 강사 공고 판별·분류 규칙: [config/keywords.yaml](config/keywords.yaml)

## 설정 방법 (처음 한 번)

### 1. Gmail 앱 비밀번호 만들기

울산판과 같은 계정을 쓰면 이미 만든 앱 비밀번호를 그대로 쓰면 됩니다.

1. 보내는 데 쓸 Google 계정에 [2단계 인증](https://myaccount.google.com/signinoptions/two-step-verification)을 켭니다.
2. [앱 비밀번호](https://myaccount.google.com/apppasswords)에서 새 앱 비밀번호(16자리)를 만듭니다.

### 2. GitHub Secrets 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 등록합니다.
울산 저장소(ulsan-shcool-public-company)와 같은 값을 쓰면 됩니다.

| 이름 | 값 | 필수 |
|---|---|---|
| `SMTP_USER` | 보내는 Gmail 주소 | ✅ |
| `SMTP_APP_PASSWORD` | 위에서 만든 앱 비밀번호 16자리 | ✅ |
| `MAIL_TO` | 받는 주소 (여러 명이면 쉼표로 구분). 비우면 `SMTP_USER` 로 보냄 | |
| `WORK24_API_KEY` | [고용24 Open API](https://www.work24.go.kr/cm/e/a/0110/selectOpenApiIntro.do) 채용정보 인증키 | |

- `WORK24_API_KEY` 가 없으면 고용24만 건너뛰고 나머지는 정상 수집합니다 (수집현황에 '설정필요'로 표시).
- `SMTP_USER`·`SMTP_APP_PASSWORD` 가 없으면 메일을 켠 실행은 실패합니다 (메일을 끈 시험 실행은 됩니다).

### 3. 시험 실행

**Actions → 매일 강사 공고 수집·메일 발송 → Run workflow** 를 누르면 바로 한 번 실행됩니다.

- **메일 발송** 칸을 끄고 실행하면 수집·엑셀만 하고, 결과는 실행 기록의 로그와 Artifacts(엑셀)에서 봅니다.
- 메일을 켜고 실행해서 메일이 오면 설정 완료이고, 이후 매일 자동으로 실행됩니다.
- 첫 메일에는 최근 45일 안에 올라온, 마감 전 공고가 모두 신규로 들어갑니다.
- 실행이 실패하면 GitHub 가 저장소 주인에게 실패 알림 메일을 보냅니다.

## 동작 방식

```
sources.yaml 의 게시판·API ──▶ 수집 ──▶ 강사 공고 판별·분야 분류 ──▶ DB(신규·중복 판정)
                                                                        │
       메일(강사잇다 양식 첨부) ◀── 공고문에서 수업 일정 등 찾기 ◀──────┘
```

- 수집 기록(SQLite)은 저장소의 `state` 브랜치에 저장됩니다. 지우면 다음 실행 때 모든 공고가 다시 신규로 옵니다.
- 메일 발송에 실패한 날의 공고는 다음 날 다시 신규로 보내집니다.
- 한 사이트가 고장 나도 나머지는 계속 수집하고, 실패한 사이트는 끝에서 한 번 더 시도합니다. 그래도 안 되면 메일 상단에 표시됩니다.
- 수집이 20분을 넘으면 남은 사이트는 건너뛰고 메일부터 보냅니다 (건너뛴 사이트는 보충 수집 대상).

## 규칙 바꾸기

- **강사 공고로 볼 단어·뺄 단어**: `config/keywords.yaml` 의 `include` / `exclude` / `result_notice`
- **포함 단어가 들어 있지만 다른 뜻인 낱말**: `config/keywords.yaml` 의 `include_ignore` (예: '건강사업' 속 '강사')
- **게시판 하나만 포함 단어를 좁히기**: `sources.yaml` 의 그 게시판 `options.include` (예: 체육시설관리사업소 공지)
- **합격자 발표 같은 결과공고도 받기**: `keep_result_notices: true`
- **분야 분류**: `config/keywords.yaml` 의 `categories` (위에서부터 먼저 맞는 분야, `!단어` 가 있으면 그 분야는 건너뜀)
- **게시판 추가**: `config/sources.yaml` 에 항목 추가. 구조를 모르면
  **Actions → 사이트 진단 (probe) → Run workflow** 에서 `--no-reach --parse --url <목록 주소>` 로 먼저 확인하고,
  넣은 뒤에는 같은 화면의 `check` 칸에 소스 id 를 적어 시험 수집합니다.
